Erklärung: _draw_token

2. Farb-Styling nachschlagen
python
style = COLOR_STYLES[color]
COLOR_STYLES ist ein Dict, das zu jeder Spielerfarbe ein Style-Dictionary liefert. Vermutlich mit Keys wie "face", "edge" und "mark":

face = Hauptfläche

edge = dunklerer Rand (für den Schatten-Effekt)

mark = Farbe für Symbole (z. B. gekreuzte Säbel)

So bleibt das Design an einer Stelle zentral definiert und die Methode ist frei von hartkodierten Farbwerten.

3. Geometrie: Innenrechteck und Eckenradius
python
inset = size * 0.075
x0, y0 = x + inset, y + inset
x1, y1 = x + size - inset, y + size - inset
radius = size * 0.13
inset = 7,5 % Rand pro Seite → das eigentliche Rechteck ist etwas kleiner als size.

(x0, y0) und (x1, y1) sind die linke obere bzw. rechte untere Ecke dieses Innenrechtecks.

radius = 13 % der Größe als Eckenradius für die abgerundeten Rechtecke.

Merke: Alles wird relativ zu size berechnet. Das ist wichtig, damit der Token bei jeder Größe (Vorschau vs. Spielfeld) gleich aussieht. Solche „Magic Numbers" wie 0.075 sind typisch — sie sind Design-Entscheidungen, keine Physik.

4. Der „3D-Effekt" durch zwei Schichten
python
rounded_rect(canvas, x0, y0 + size * 0.035, x1, y1 + size * 0.03, radius, fill=style["edge"])
rounded_rect(canvas, x0, y0,               x1, y1 - size * 0.01, radius, fill=style["face"])
Hier passiert der Trick: Es werden zwei abgerundete Rechtecke übereinander gezeichnet:

Erste (hinten): um ca. 3–3,5 % nach unten verschoben, Farbe edge (dunkel) → wirkt wie ein Schatten / Seitenkante.

Zweite (vorne): normal positioniert, leicht nach oben gezogen (unten -1 %), Farbe face (hell) → die Oberfläche.

Ergebnis: ein Token, der aussieht, als hätte er Dicke — wie ein Stück Plastik auf dem Tisch. Das ist ein klassischer 2D-Trick („fake extrusion"), ohne echte 3D-Renderung.

Beachte: Das zweite Rechteck ist unten etwas kürzer (y1 - size*0.01), damit der Schatten unten leicht rausschaut — das verstärkt den Effekt.

5. Zentrum berechnen
python

center_y = y + size / 2
Alle Symbole orientieren sich am Mittelpunkt des Tokens. Die Methode rechnet bewusst von x, y (Ecke) nach center_* — Caller-Code kann also einfacher mit Ecken arbeiten.

8. Didaktische Takeaways
Relative Koordinaten (size * k) überall — macht die Methode größenunabhängig. Faustregel: keine absoluten Pixel außer als Mindestwerte (max(2, …)).

Layering als Design-Technik — zwei Rechtecke = Pseudo-3D. Günstig und effektiv.

Single Source of Truth — Farben kommen aus COLOR_STYLES, nicht aus der Methode. Ändert man das Design, ändert man nur das Dict.

Early Return bei rank is None — hält den Code flach, statt in ein großes if rank is not None: einzupacken.

Enum mit is vergleichen — korrekt bei Python-Enums.

Delegation — Bombe/Flagge sind in eigene Methoden (_draw_bomb, _draw_flag) ausgelagert. Die Hauptmethode bleibt lesbar, auch wenn's nur ein Symbol betrifft.

Guard-Clauses für Schriftgrößen — max(2, size*0.04) verhindert unsichtbare Linien bei Mini-Tokens.

9. Kleine Schwachstellen / Diskussionspunkte
Magic Numbers wie 0.075, 0.035, 0.11, 0.24 sind nirgends benannt. In einem größeren Projekt würde man sie als Konstanten (TOKEN_INSET_RATIO, …) auslagern — oder als kleines Layout-NamedTuple.

Der Parameter x, y als Ecke ist nicht offensichtlich aus dem Namen — ein Docstring wäre hier Gold wert („Zeichnet einen Token mit linker oberer Ecke bei (x, y)").

style["face"] etc. sind String-Keys — ein TypedDict oder @dataclass würde Tippfehler zur Laufzeit vermeiden helfen.
